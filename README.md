# Who will be frozen first? — ARG-голосование

Статический сайт в стиле ARG (чёрный фон, белый текст, глитчи, шум, «тревожная» типографика).
Голос сохраняется прямо в репозиторий — в файл `votes.json` через GitHub REST API.

## Файлы

- `index.html` — разметка
- `style.css` — стили и атмосфера
- `app.js` — логика голосования и работа с GitHub API
- `config.js` — **настройки (заполнить)**
- `votes.json` — файл с результатами (создаётся заранее, обновляется ботом)

## Настройка (пошагово)

1. Создай GitHub-репозиторий, залей туда все эти файлы.
2. В репозитории: **Settings → Pages → Build and deployment → Source: Deploy from a branch**,
   выбери ветку `main` и `/ (root)`. Сохрани.
3. Создай Personal Access Token:
   - **Fine-grained token** (рекомендуется): выбери только этот репозиторий,
     в `Contents` поставь **Read and write**. Срок — минимально возможный.
   - Либо **Classic token** с единственной галочкой `public_repo` (для публичного репо).
4. Открой `config.js` и заполни `owner`, `repo`, `branch`, `token`.
5. Закоммить изменения. Готово — при голосовании `votes.json` будет обновляться,
   а в истории коммитов появятся записи `arg: record vote`.

## Как работает защита от повторного голосования

- В `localStorage` браузера сохраняются `arg_vote_choice` и `arg_voter_id`,
  поэтому после перезагрузки страницы повторно проголосовать нельзя.
- Дополнительно ID посетителя записывается в массив `voters` в `votes.json`
  и проверяется при каждой загрузке/голосовании.

## Важное предупреждение про безопасность ⚠️

Токен хранится в `config.js`, а значит **виден всем**, кто откроет исходники сайта.
Для ARG-проекта это обычно приемлемо, но помни:

- любой желающий сможет проголосовать за всех или испортить `votes.json`;
- токен нельзя использовать для чего-то ещё — только для этого репозитория;
- не публикуй репозиторий с реальным токеном, если тебе важен результат.

Если нужна настоящая защита, вынеси запись результатов на небольшой сервер
(или GitHub Actions + `repository_dispatch` с токеном в Secrets) — тогда токен
не будет доступен в браузере. При желании могу переделать под такой вариант.

Ограничение localStorage: если посетитель вручную очистит данные сайта, он получит
новый ID и сможет проголосовать снова. Полностью победить это без серверной части
(учёт по IP/аккаунту) невозможно.
